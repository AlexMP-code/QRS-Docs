# นัดหมายที่พ้นวันให้บริการเปลี่ยนเป็น "ไม่มาตามนัด" โดยระบบ

วันให้บริการของนัดหมายผ่านไปแล้ว แต่สถานะยังเป็น "ยืนยัน" นัดหมายนั้นถูกนับเป็นคิวค้างต่อไปเรื่อย ๆ ทำให้ข้อมูลเพี้ยนถาวร และบล็อกการเปลี่ยนแปลง config ของศูนย์สุขภาพ — `CloseHealthCenterJob` เช็ค `status = CONFIRMED` โดยไม่กรองวันที่ คิวที่จบไปแล้วหนึ่งเดือนก็ยังบล็อกการปิดศูนย์ ระบบไม่มี scheduler จึงไม่มีอะไรมาเปลี่ยนสถานะนี้เลย

## Considered Options

- **ปล่อยให้ค้างเป็นยืนยันถาวร รอมนุษย์จัดการ** — ไม่ต้องเพิ่มกลไกใด แต่สถิติคิวค้างจะเพี้ยนทุกวัน และศูนย์ที่ไม่มีความเคลื่อนไหวจะปิดไม่ได้เลย
- **เพิ่มสถานะใหม่ เช่น "หมดวัน" ที่ยังไม่จบ** — ต้องแก้ทุกที่ที่กรองสถานะ ทั้งโควตา การนับ และหน้าจอ เพิ่มสถานะที่ไม่มีใครดำเนินการต่อ
- **ให้ระบบเปลี่ยนเป็น "ไม่มาตามนัด" เอง เมื่อพ้นวัน** — ใช้สถานะที่มีอยู่แล้ว สถิติจึงสะท้อนความจริง

เลือกข้อสุดท้าย เพราะการที่ยังอยู่ในสถานะยืนยันไม่ได้แปลว่ายังรออยู่จริง และการเพิ่มสถานะใหม่คือการสร้างภาระให้ทุกจุดที่ต้องตัดสินใจว่าจะนับสถานะนั้นอย่างไร

## Implementation

- งานตามเวลาที่กำหนด (ทุกวัน) ไม่ใช่ตอนมีคนทำรายการ — ศูนย์ที่ไม่มีความเคลื่อนไหวต้องถูกจัดการเช่นกัน ไม่ใช่เฉพาะศูนย์ที่มีคิว
- เกณฑ์คือพ้น **วันให้บริการ** ไม่ใช่พ้นเวลาในช่วงเวลา
- การกรองคิวค้างที่ใช้บล็อกการเปลี่ยนแปลง config ทุกจุด ใช้เกณฑ์เดียวกัน (ตั้งแต่วันนี้ขึ้นไป) ให้ตรงกัน

## Consequences

- **เกณฑ์เดิมที่ว่า "สถานะหลังเป็นปลายทาง" มีข้อยกเว้นหนึ่ง** — "ไม่มาตามนัด" ที่ระบบเป็นผู้เปลี่ยน แก้กลับเป็น "เสร็จสิ้น" ได้ เพราะเจ้าหน้าที่อาจลืมปิดคิว และข้อมูลต้องตรงกับความเป็นจริง — ถ้าเป็นคนที่กดเอง นับเป็นปลายทางถาวร เพราะการกดด้วยเหตุผลของคนแล้วถอดไม่ได้
- ยอมรับว่าเจ้าหน้าที่ที่ปิดคิวหลังสิ้นวันแล้วต้องกดแก้คืน ไม่ใช่รอให้ระบบช่วย
- **การแก้กลับไม่ต้องใส่เหตุผล** และไม่จำกัดช่วงเวลา เพราะข้อเท็จจริงที่ว่าผู้รับบริการมาจริงหรือไม่ไม่มีวันหมดอายุ ผลคือ **การทับข้อมูลที่ระบบเพิ่งเขียนไม่มีร่องรอยว่าใครทำ** — ถ้าภายหลังต้องการตามกลับจะย้อนไม่ได้
- ต้องมีตารางงานประจำวัน ซึ่งระบบยังไม่มี — เป็นการเพิ่มส่วนประกอบที่ต้องดูแลต่อไป ไม่ใช่แค่ปล่อยงานค้างในคิว
- นัดหมายที่ถูกระบบเปลี่ยนสถานะเท่านั้นที่ย้อนกลับได้ ต้องแยกให้ออกจากที่คนกดเองในระดับข้อมูล ไม่ใช่เดาจากเวลาหรือสถานะปัจจุบัน
- ปัจจุบันการเปลี่ยนสถานะนัดหมาย **ไม่ถูกบันทึกลง AuditLog เลย** ซึ่งทำให้ข้อยกเว้นข้างบนแย่งกับการแก้กลับที่คนทำเอง — ต้องใช้คอลัมน์เวลาเป็นตัวตัดสิน ไม่ใช่ log
